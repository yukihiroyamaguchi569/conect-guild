- 社長が遊びの機能の案から「仕事をたくさんした人にはご褒美」を選び、「その日の一番にだけ」「夕方（17 時）に届き、その日のあいだ机に置く」「おにぎり・おだんご・勲章をランダム」と決めた。絵は #199 で入れた `onigiri`・`dango`・`medal` をそのまま使う
- クリアは机のクリア（出来事の「クリアした！」）と同じ数え方にした。レベルの経験値は履歴に時刻が無いため、その日の分は snapshot の閉じた Issue の `closedAt` から数える（実装時の判断）
- 同点は先にその数に達した人、0 件の日は無し。かなめと王様は対象外（実装時の判断。DESIGN.md 8 章に理由）
- 何が届くかは日付から決まる乱数にした。読み込み直しても同じものが選ばれる（実装時の判断）
- 届いたときの一行は、出来事（`GuildEvent`）ではなく、お客さんの出来事と同じくお知らせのメッセージとして出す。出来事にすると演出・効果音・メッセージの送りの全部に手が入るため。歩く演出は足していない（置くだけ）
- codex のレビューで、届いたあとに Issue が開き直されると机のごほうびが動く、クリアが遅れて届くと言わない、取得の失敗が続くと 0 時を過ぎても残る、17 時より後に開いた画面で古い snapshot から言ってしまう、隠れたページで翌日に言う、開き直した画面では Issue の開き直しで動く、翌日に届いた取得で言う、古い snapshot で消える、開き直して取得に失敗すると置かれない、などの指摘を受け、その日のごほうびを固定して localStorage にも残し（`watchReward`、時刻・部門の番号・種類だけ）、描くときに 0 時を見て、その日を過ぎた取得では言わず、順番が来たのが 0 時より後の一行は捨てる（メッセージのキューに `until` を足した）ようにした。どれも回帰テストを足した
