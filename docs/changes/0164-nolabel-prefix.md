# #164 ラベルの無い Issue を、結び付いた PR の接頭辞で部門に置く（2026-10-17）

- 部門のラベルを付けない運用の会社では、Issue がすべてかなめの受付に積まれ、部門は何もしていないように見えた。PR はすでに、結び付いた Issue のラベルで決まらなければブランチ名の接頭辞（`branchPrefixes`）で部門が決まっていたが、Issue は接頭辞を見ていなかった
- 案 A（接頭辞から部門を決める）を採った（社長の判断、2026-10-17）。題名の書き方から決める案 B、スキルがラベルをまとめて付ける案 C は、あとで決める
- 部門のラベルがある Issue は今までどおりラベルで決める。ラベルが無い開いている Issue は、結び付いた開いている PR の接頭辞が 1 つの部門にそろったときだけその部門に置き、PR が無い・当たらない・割れるときは受付のまま
- 接頭辞の判定は PR の担当（`assignPr`）と同じ `departmentFromBranch` を使う。接頭辞が部門に当たらない PR は「割れる」に数えないのは実装時の判断
- 掲示板の欄だけでなく、メンバーの working・done、受付の件数、Issue が開いた・閉じたときの演出も同じ判定にそろえた（画面の中で置き場所が食い違わないように）
- 閉じた Issue の部門は、結び付いた開いている PR に加えてマージ済みの PR の接頭辞も数える。はじめは開いている Issue だけにしていたが、PR が開いたまま Issue を閉じるとクリアが受付に出て直前の机と食い違うと codex のレビューで指摘され、さらに主な経路である PR のマージで閉じたときも受付に出るので、マージ済みの PR も数えることにした（司令塔の判断、2026-10-17）。マージ済みの PR は collector がすでに snapshot の `prs` に入れている（直近 7 日）ので、collector は変えていない。マージせずに閉じた PR は数えない。開いている Issue の置き場所は今までどおり開いている PR だけで決める
- DESIGN.md の 4.5「Issue の担当」を直した
