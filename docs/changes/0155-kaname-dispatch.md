# #155 かなめが部門に仕事を振る形の呼びかけ（2026-10-15）

- 社長がかなめに指示し、かなめが総務に仕事を振ったとき、画面では王様が総務に直接「！」「ゴニョゴニョ」と話しかけた形になった（社長、2026-10-15）。王様の呼びかけ（#28）は部門のセッションが作業中になったことを社長の指示とみなすだけで、誰が話しかけたかは分からないため
- 社長の判断（案 A）: 部門のセッションが作業中になった取得の 60 秒前までにかなめのセッションが作業中だったら「かなめが振った」とみなし、かなめが受付で部門のほうを向いて「おねがい！」、部門が席でかなめのほうを向いて「はい！」と返す。王様は黙ったまま。かなめが待機していたなら今までどおり王様が話しかける。同じ取得でかなめも作業中になったら今までどおり王様の呼びかけ。社長がかなめと話している間に部門へ直接指示すると、かなめが振った形に見えることがあるが、受け入れる
- 判定は `domain/summons.ts` の純粋関数（`lastKanameWork`・`summonsFrom`、`KANAME_DISPATCH_WINDOW_MS` = 60 秒）。かなめが最後に作業中だった時刻は、比較元の読み取りと同じくストアが持ち、halted と、セッションが `unavailable` か古い取得で忘れる（実装時の判断。古い情報からかなめが振ったとみなさないため）。許可待ちのかなめは作業中に数えない
- 演出は `render/summons.ts`。時間は `SUMMONS.askMs`（1.4 秒）を足し、「はい！」は今までの返事と同じ `replyMs`（1.6 秒）。全部で 3 秒。部門が複数のとき、かなめは並びの最初の部門のほうを向く（実装時の判断）。吹き出しは「はっ！」と同じ話す形、効果音は今までの呼びかけと同じ
- 王様の暇: かなめの呼びかけでは王様を留めず、起こさないので、呼びかけのあとに王様の暇を数え直すのは王様の呼びかけが終わったときだけにした（王様の呼びかけのあとにかなめの呼びかけが続くときは、王様の呼びかけが終わったところで数え直す）
- デモ（4.11）: 頭のかなめへの指示から 60 秒以内に部門が作業を始めるので、16.5 秒・25.5 秒・33 秒の部門の作業はかなめが振る形になった。台本は変えていない。DESIGN.md 4.11 の「王様の指示」を直した
- テスト: vitest（判定の 60 秒の境目、同じ取得でかなめも変わる、かなめが待機、halted・古い読み取り・短い取得失敗のあと、デモでかなめが振る形になること、演出の配役と時間、向き、留める位置、演出に取られたときに言葉を終えること、王様の暇を数え直す時、吹き出しが窓・タグにかからないこと）。e2e は `kanameVisit.spec.ts` に「かなめが作業中のあと部門が作業中 → かなめの『おねがい！』と部門の『はい！』、王様は黙る」を 1 つ足した
