# #79 セットアップの方法（npm run settings:write）（2026-10-13）

- 手元の設定を作る道具を「書く・検証する土台」と「入口」に分け、土台の `npm run settings:write` を先に作った。入口は Claude Code のスキルにする（社長の判断）が、この PR には入れない（DESIGN.md 10 章 9）
- 2 段にした: `--dry-run` は書かずに確認の表と警告・エラーを出し、入口が社長の OK をもらってから `--write` で書く（スキルは端末の y/n に答えられないため。社長の判断）
- ラベルを GitHub に問い合わせられないときは警告して書く。collector が起動時と 10 分ごとに照合し直す（#85）ので気づける（社長の判断）
- 取り違えへの備え: 部門のフォルダの `CLAUDE.md` にその部門のラベルがあるか、接頭辞とフォルダ名が合うかを突き合わせて警告する（止めない）。`CLAUDE.md` はラベルの有無だけを見て、中身は保存・表示しない（社長の判断）。上書きの前に前の設定を `guild.settings.local.json.bak` に残す
- 実装時の判断: 置き場所は `packages/collector`（gh の呼び方・ラベルの照合・原子的な書き込みをそのまま使うため）。既存の手元の設定があるときの `--write` は `--overwrite` を要る形にした（Issue の「上書きは `--overwrite` か確認なしには行わない」）。メンバーの役は、ラベルと同じだったときだけ新しいラベルに合わせる。`branchPrefixes` は入力の 4 行の後ろに、まだ使える既存の行（`docs/` で始まるものなど）を保つ。`expandHome` を `src/home.ts` に移し、設定の schema を `@conect-guild/snapshot/settingsSchema` から読めるようにした（どちらも設定を読み込まずに使うため）
- docs/setup.md の 2 章に、道具の使い方（2-2b）を足した。2 章の最初を道具にする書き換えと orchestration.md の 3-6 は、入口のスキルを足すときに行う
- レビューの指摘: 検証エラーに外から来た文字（重複したラベル、知らない項目名）が入ると、改行や制御文字で偽の行を作れた。設定の schema の検証エラーを `describeIssues`（`z.prettifyError` と同じ形で、メッセージとパスの改行・制御文字をエスケープ）で出し、重複の値は JSON の文字列で示すようにした。collector と開発サーバーが設定の誤りで止まるときの文言もこの形になる。道具の出力（表・警告・エラー・`--json`）でも制御文字をエスケープする
- レビューの指摘: 新しく書くときは、確認のあとに別の処理が作った `guild.settings.local.json` を上書きしないよう、一時ファイルからハードリンクで作る（あれば失敗する）
