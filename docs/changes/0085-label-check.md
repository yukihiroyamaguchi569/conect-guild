# #85 collector: 設定の部門ラベルがリポジトリに無ければ知らせる（2026-10-13）

- docs/orchestration.md 3-2 で「ラベル名は conect-guild の設定（`departments[].label`）と 1 文字も違わないようにする」と手作業の注意を書いていたが、食い違うと Issue が部門に振られず受付に残り、どこが違うかに気づきにくい。#83 のレビューで社長が「自動で確かめられないか」と提案し、#85 に分けた。#79（セットアップの方法）より先にやるのは、どちらの方式でも検証の部品として使え、手で直した後や GitHub でラベル名を変えた後の見張りとしてずっと要るため（社長の判断）。次のようにした（DESIGN.md 4.1・4.3）
- 照合の頻度: collector の起動時に 1 回、そのあと 10 分ごと。GitHub の 60 秒ごとの取得とは別の予定で、裏で走らせる（社長の判断。collector が常駐することを確かめたうえで）
- 取得: 対象リポジトリのラベル名だけを `gh api --paginate --jq` で 1 行 1 JSON で受け、行ごとに zod で検証する（既存の流儀どおり）
- 照合は純粋関数 `missingLabelPositions`（設定の部門とラベル名の一覧 → 無い部門の添字）にし、collector の内部の状態に頼らない形にした。#79 の設定の確かめからも呼べるように（社長の判断）。比べ方は collector が Issue のラベルを部門に結ぶときと同じ完全一致
- 知らせ方: 無い部門の添字を `collector-status.json` の `missingLabels` に足し、画面の帯と docs/setup.md の直し方へのリンクで出す。ログには `departments[n]` の添字と件数だけを出し、ラベル名は出さない（社長の判断）
  - `missingLabels` は無い部門があるときだけ書き、全部あるときと、まだ分からないときは項目ごと書かない。#74 の状態ファイルをそのまま読める形を保つため（実装時の判断）
  - 帯は本物の画面だけに出す。#74 の帯は自動のデモ（snapshot がまだ無い）の間だけだったが、ラベルの食い違いは snapshot が書けている本物の画面で困るため、本物の画面でも状態ファイルを読むようにした。`?demo=1` と自動のデモでは出さない（実装時の判断）
  - 帯のラベル名は、状態ファイルの添字から画面が読んだ設定で引く（状態ファイルとログにはラベル名を入れない）。5 分より古い状態は、collector が止まった後として出さない（#74 と同じ決まり。実装時の判断）
  - ログは結果が変わったときだけ出す（10 分ごとに同じ行を出さない。実装時の判断）
- ラベルの取得に失敗しても snapshot の更新と終了コードは変えない。失敗は「分からない」として扱い、「無い」と知らせない。最後に取れた結果を残し、次に取れたときに置き換える（直れば帯から消える）（社長の判断。取れなかったときに前の結果を残すのは実装時の判断）
- docs/setup.md の「困ったとき」に、この帯が出たときの確かめ方と直し方を足し、docs/orchestration.md 3-2 に「食い違うと collector が帯で知らせる」を書き足した
