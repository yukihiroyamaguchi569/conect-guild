# #256 e2e を shard で分けて同時に走らせ、待ち時間を短くする（2026-10-23）

- CI の e2e のテスト本体（約 7〜8 分）を、matrix で 4 つの shard（`npm run test:e2e -- --shard=i/4`）に分けて同時に走らせる。CI の利用時間は増えるが、待ち時間を優先する（社長の判断）
- shard の数を 4 にした理由（実装時の判断）。テストは 98 本・27 ファイルで、`fullyParallel: false` なので shard にはファイル単位で分かれる。一番長い `demo.spec.ts` が 1 ファイルで約 2 分かかり、どの shard の数でもこれより短くはならない。#255 の CI で測った時間で shard ごとのテストの時間を見積もると、一番長い shard は 2 で約 4 分、3 で約 3 分 15 秒、4 で約 2 分 40 秒。shard ごとの準備（コンテナ約 30 秒、setup-node と npm ci 約 10 秒、9 つの開発サーバーの起動約 15 秒）は 1 分ほどで、4 までは待ち時間が縮む
- どの shard でも `playwright.config.ts` の開発サーバー（9 つ）を全部立てる。Vite の開発サーバーでビルドは無く、起動は 15 秒ほどなので、shard ごとに重ねても重すぎない。テストは shard の中でこれまでどおり 1 本ずつ順に動かす
- `fail-fast: false` で、1 つの shard が失敗してもほかの shard を最後まで走らせる。失敗時のレポートは `playwright-report-<i>` の名前で shard ごとに残す（レポートを 1 つにまとめるジョブは作らない）
- PR の画面の検査名は「E2E / e2e」から「E2E / e2e (1, 4)」〜「e2e (4, 4)」に変わる。ブランチ保護の必須の検査は設定されていない（2026-10-23 確認）
