# #253 お試しの会社を消す・名前を変える前の確かめをコードで行う（trial:check）（2026-10-23）

- `/guild-trial-cleanup`（`gh repo delete`・`rm -rf`）と `/guild-trial-renew`（`gh repo rename`・`mv`）は、対象がお試しの会社かを Claude が SKILL.md の文章を読んで確かめていただけだった。読み違えると本物の会社のリポジトリやフォルダに手が届くので、確かめを道具 `npm run trial:check`（`packages/collector/src/trialCheck.ts`）に移した。スキルは道具が終了コード 0 で出したリポジトリとフォルダだけを、消す・名前を変える・移すコマンドに使う
- 形は 3 つにした（実装時の判断）。`cleanup` は、フォルダが無いがリポジトリと設定が残っている、リポジトリはもう無いがフォルダが残っている、のような途中の状態も片付けるので、全部満たすかどうかではなく、消してよいもの（`repo`・`folder`・`settings`・`settingsBak`）と消さないものの理由（`kept`）を出す。確かめられないときだけ 1 で止まる。`renew` は作ったままのお試しを全部の条件で確かめる。`renewing` は、renew が最初に説明を `<新> の会社` に変えたあと（`renew` は通らなくなる）の、名前を変える前と移す前に使う
- 名前の形と印は `trialCells.ts`（`trial:open-cells`）のものを使い回す。名前の形の正規表現を、今の形（`guild-trial`・`guild-trial-<番号>`）と前の形（`<日付>-<4 文字>`）に分けて公開した。`TRIAL_NOTE` は `trialScaffold.ts` から公開した
- `gh repo view` が「リポジトリが無い」以外で失敗したとき（sandbox の中での証明書のエラーを含む）と、応答が形に合わないときは、確かめられないとして止まる（安全側）。npm の中から `gh` を呼ぶので、スキルは `trial:check` の行を初めから sandbox の外で実行する
- cleanup の承認の一覧に、フォルダもゴミ箱を通らず元に戻せないことを書いた（リポジトリは前から書いてあった）
- 司令塔の `CLAUDE.md` がシンボリックリンクなら、cleanup もお試しのフォルダと認めない（前は renew だけが見ていた。実装時の判断。安全側に寄せた）
- cleanup がフォルダを消してよいと認めるのは、司令塔の `CLAUDE.md` の印に加えて、`origin` が `<owner>/<名前>` を指すときだけにした。印は部分文字列なので、どんな文書にも書ける。`/guild-trial` は `gh repo create --source --push` で必ず `origin` を付ける。`origin` が無い・違うフォルダは消さない（統合レビューの指摘）
- 前の形 `<日付>-<4 文字>` のリポジトリは説明が無いので、cleanup が説明を問わずに消してよいとするのは、お試しのフォルダ（印と `origin`）がそのリポジトリを指すときだけにした。前は手元の設定が指すだけでも消してよいとしていて、お試しを手で消したあとに同じ名前で作った本物の private のリポジトリが `gh repo delete` に渡りえた。フォルダが無いときは残し、手で消してもらう（統合レビューの指摘）
- `renew` はリポジトリの id（`gh repo view --json id` の node id。名前を変えても変わらない）を出し、`renewing` はそれを受け取って、旧名・新名のどちらで見つけても id が同じときだけ通す。新しい名前に別の private のリポジトリがあり説明が `<新> の会社` でも、名前を変える・移す段に進まないため。スキルは id を承認の一覧に書き、会話が切れたあとの続きでは利用者に写してもらう（統合レビューの指摘）
