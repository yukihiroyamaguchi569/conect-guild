# #67 初回起動で /snapshot.json が 404 になりサーバーエラーと出る（2026-10-12）

- collector（`npm run collect`）を一度も動かしていないと `apps/web/.data/snapshot.json` が無く、開発サーバーが 404 を返す。画面はこれをほかの HTTP エラーと同じ `reason: 'http'` にして「取得失敗（サーバーがエラーを返しました）」と出していた（メンターの報告）
- 「まだ集めていない」を `reason: 'not-collected'` として分けた。500 などは `http` のまま（DESIGN.md 4.3）
- 最初は「まだ データを あつめていません」の案内の窓（`npm run collect` か `?demo=1` へのリンク）を出す形で作ったが、社長とメンターの判断（「だれでも起動だけで見える状態に」）で、最初の snapshot の前にデータが無ければ自動でデモを流す形に変えた。案内の窓は消した（DESIGN.md 4.3、4.11）
  - 台本は `?demo=1` と同じ。「▶ はじめる」は出さず、Canvas が準備できて画面に出たら自動で始める。ブラウザはクリックの前に音を出せないので無音で始め、「♪ 音を出す」で鳴らせる。`?demo=1` を明示したときは今までどおり「はじめる」から
  - 画面の上に「デモ表示中（架空のデータ）。データを集めると自分のリポジトリに切り替わります」の帯と、docs/setup.md へのリンクを出す。開発サーバーは `docs/` を配らないので GitHub の公開ページへのリンクにし、新しいタブ・`rel="noopener noreferrer"` で開く。画面からは何も読み込まない。conect-guild 自体の URL は `apps/web/src/project.ts` に 1 か所だけ置く。CLAUDE.md の「ブラウザから外部へ通信しない」との関係は DESIGN.md 4.3 に書いた（社長の判断）
  - 自動のデモの間も裏で 5 秒ごとに `/snapshot.json` を読み、「まだ集めていない」以外が返ったら本物に切り替える。500・ネットワーク・検証失敗も本物の画面に戻し、これまでどおりエラーを出す（デモで隠さない。実装時の判断）
  - 切り替えは `App.vue` が画面（中身は `App.vue` から `ui/GuildScreen.vue` に移した）を `key` で作り直して行う。ストア・音・ナレーション・Canvas がすべて新しくなるので、デモの状態や基準（メモリだけ）が本物に混ざらない。本物の最初の取得は、基準が無ければ基準になるだけで出来事は出ない（実装時の判断）
  - 一度 snapshot を表示した後に「まだ集めていない」が返ったときは、デモにせず「取得失敗（データのファイルがありません）」にした。前回の表示が残っているため（実装時の判断）
- README の「デモモードで見る」を「起動するだけでデモが動く」に合わせて直し、docs/setup.md の手順に `npm run collect` を先に動かすこと、まだ集めていない間はデモが流れることを書いた
- 最初は開発サーバーの 404 を「まだ集めていない」と読んでいたが、Chrome は失敗した fetch をコンソールのエラーとして記録するので、自動のデモの間 5 秒ごとに 404 のエラーが出て、初めて触る人には壊れて見えた。開発用の Vite プラグインは、ファイルがまだ無いときに 204 No Content（`Cache-Control: no-store`、本文なし）を返すようにし、画面は 204 を `not-collected` として読む。404 は（ルートの間違いなどの）通常の HTTP エラーに戻した（社長の判断。DESIGN.md 4.1・4.3）。E2E は自動のデモの間コンソールのエラーが 0 件であることを確かめる
- 統合レビュー（gpt-6-sol）の指摘 3 件を直した（すべて採用。DESIGN.md 4.3、4.11）
  - localStorage に古い基準が残っていると、自動のデモから本物に移った直後の取得で出来事がまとめて出た。自動のデモの後の本物のストアは保存済みの基準を捨て、最初の snapshot を新しい基準にする（前に「ふつうの読み込みと同じ」としたのを、社長の判断で直した）
  - 幅 760px 以下では Canvas が隠れて自動のデモが始まらず、帯だけが出ていた。自動のデモは Canvas の準備ができたら狭い画面でも始め、見えない Canvas の演出だけを捨てる。`?demo=1` の「狭い画面では はじめる を押せない」は撮影用なのでそのまま
  - 監視中の 500・404・ネットワークエラーで本物に戻しても、作り直した画面の取得が 204 だとデモに戻り、エラーが一度も出なかった。切り替えを決めた結果を新しいストアの最初の結果として渡す。そのあと 204 が返ればデモに戻す（まだ集めていないのは事実で、エラーは一度は出るため。実装時の判断）
- 統合レビュー 2 周目（gpt-6-sol）の指摘を直した: 上の 1 件目の対応は、本物のストアを作った時点で保存済みの基準を消していたので、エラーで切り替わって次の 204 でデモに戻ると、正常な snapshot を一度も受け取らないまま基準が失われた。基準を置き換えるのは、自動のデモの後に最初の正常な snapshot を適用するときだけにした（DESIGN.md 4.3）
