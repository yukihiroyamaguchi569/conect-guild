# #67 初回起動で /snapshot.json が 404 になりサーバーエラーと出る（2026-10-12）

- collector（`npm run collect`）を一度も動かしていないと `apps/web/.data/snapshot.json` が無く、開発サーバーが 404 を返す。画面はこれをほかの HTTP エラーと同じ `reason: 'http'` にして「取得失敗（サーバーがエラーを返しました）」と出していた（メンターの報告）
- 404 を `reason: 'not-collected'` として分け、最初の snapshot の前なら「取得失敗」の代わりに案内の窓（「まだ データを あつめていません」、`npm run collect` か `?demo=1` のデモ）を出すようにした（DESIGN.md 4.3）。500 などは `http` のまま
  - 表示は止めない（halt にしない）。5 秒ごとの取得を続け、collector がファイルを書けば再読み込みなしで通常の画面に移る。最初の snapshot は従来どおり基準になるだけで、演出は出ない
  - 一度 snapshot を表示した後の 404 は、案内ではなく「取得失敗（データのファイルがありません）」にした。前回の表示が残っているので、案内を重ねると紛らわしいため（実装時の判断）
  - デモへのリンクは同じオリジンの相対リンク `?demo=1` にした（外部 URL は使わない）
- README の「デモモードで見る」と docs/setup.md の手順に、`?demo=1` なしで開くと案内が出ること、`npm run collect` を先に動かすことを書いた
- Chrome は 404 の fetch をコンソールのエラーとして記録する。案内が出ている間は 5 秒ごとに 1 行出るが、画面の挙動には関係しないので、そのままにした（E2E ではこの行だけを除いて確かめる）
