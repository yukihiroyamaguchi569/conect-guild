# #18 部門の数を変えられるようにする: 2 部門と 3 部門の間取り（2026-10-14）

- 部門の数を 2〜6 で変えられるようにする（#18）うち、2 部門と 3 部門を使えるようにした。4 部門の画面とふるまいは変えていない
- 間取り（`apps/web/src/render/layouts/`）
  - `layout2.ts`・`layout3.ts` を手で作り、`catalog.ts` に登録した。床・壁・窓・掲示板・玉座・カウンター・扉と下段の 2 つの机は layout4 と同じ位置に置き、部屋の印象をそろえた。共通の部分は `smallRoom.ts` にまとめた（layout4 は golden で守っているので触っていない）
  - 社長の指示（2026-10-14）で作り替えた: 2 部門は机を 2 つとも下段（layout4 の企画・総務の位置）に置き、3 部門はそれに上段左（layout4 の経理の位置。金庫などの小物も同じ）を足した。机の並びは上段 → 下段、左 → 右（2 部門: 下段左・下段右、3 部門: 上段左・下段左・下段右）。下段の 2 つは layout4 と同じ小物（地球儀、書類の山と砂時計）で左右でおしゃべりし、3 部門の上段左はそろばんと金貨で、おしゃべりの相手は無し（相手は対でないといけないため）
  - 空いた上段右は酒場（丸テーブル、樽、マグ、窓の光）にし、お客さんの場所はテーブルの左右の 2 マスにした。2 部門の上段左は書庫（奥の壁ぎわに本棚 2 つ、その前に長椅子・本・寝ている猫）。猫はベンチに重ねず、ペットのそばと右の窓の下のマスは遊びの場所として空けた。小物はすべて既存の絵（`assets/decor`）から選んだ
  - パーティ窓の下端: 行は部門＋2。2 部門（4 行）はパーティの窓の最小の高さ（`.stage__party` の 21.1cqw）で決まり、右の列の下端は 4 部門より 49.2 px 上（デモ、1024 px、Chrome で 273.3 px と 322.4 px）。3 部門（5 行）は 1 行ぶん 38.0 px 上（284.5 px）。layout4 の 340 px（失敗の行あり）と 372.5 px（まれな注意書きまで）から引いて切り上げ、2 部門 291・324、3 部門 303・335 にした
- 設定
  - `SUPPORTED_DEPARTMENT_COUNTS` を 2・3・4 にした。エラーの文言は「2 or 3 or 4 departments (#18)」
  - `npm run settings:write` の入力（`packages/collector/src/settingsInput.ts`）も 2〜4 部門を受ける。i 番目の部門のメンバーは出発点の i 番目のまま、出発点に無い位置にはどの部門も使っていないメンバーを `DEPARTMENT_MEMBER_IDS` の順で当てる。新しく部門に就いたメンバーの役は新しいラベルにする。出発点の設定にそのメンバーの項目が無いときは、検証が「members.<id>: missing」で止める
  - `/guild-setup` の SKILL.md と docs/setup.md は、5・6 部門と合わせて後の PR（計画の G）で直す
- デモ（`domain/demo.ts`・`domain/demoScript.ts`）
  - 部門の数に合わせた。クエストを運ぶ 2 部門は、部門の数の半分（切り上げ）を h として k 番目と k＋h 番目（k はループごとに回る）。4 部門ではこれまでどおり経理・企画 → 広報・総務の繰り返し。残りの部門から設定の順に 2 つまでが手伝い、2 部門では手伝いのレーンが無く、3 部門では 1 つ
  - 題名は部門ごとの順に、その部門が運ぶたびに次のものを使う（3 部門では同じ部門が続けて運ぶことがあるため）。6 部門まで見込んで、題名の組と架空の過去の実績を 2 部門ぶん足した（5・6 部門のレベルアップの時刻は、その間取りを足すときに合わせる）
  - 部門のラベルを引数で受けられるようにし（既定は設定のもの）、2・3 部門のテストを架空のラベルで足した。4 部門のテスト（時刻・出来事の順）はそのまま通る
- E2E
  - テストのときだけ、架空の 2・3 部門の設定（`apps/web/e2e/settings/departments-2.json`・`departments-3.json`。架空のラベルとリポジトリ）を読めるようにした（社長の承認済み）。`vite-plugin-settings.ts` は、開発サーバーが `--mode e2e-departments` で、環境変数 `GUILD_E2E_DEPARTMENTS` が 2 か 3 のときだけ、`guild.settings.json` の import をそのファイルに向ける。環境変数は決まったファイルから選ぶだけでパスを指せず、ほかの値なら止まる。`npm run dev`・build・collector はこのモードを使わないので、本番の読み方は変わらない。同時に立つサーバーが依存のキャッシュを取り合わないよう、このモードではキャッシュの置き場を分ける
  - `playwright.config.ts` に 2 部門（5197 番）・3 部門（5198 番）のサーバーとプロジェクトを足し、`e2e/departments.spec.ts` だけをそこで動かす。デモで、パーティの行数と名前、Canvas の「Lv」の数（かなめ＋部門）、最初のクエストの受け渡し、右の列の下端が間取りの値以下であること、席とお客さんの場所が実際の窓にも間取りの窓の範囲にも重ならないことを確かめる
- CLAUDE.md の「テストは常に guild.settings.json」に、この E2E だけの例外を 1 句足した。DESIGN.md の 3 章（layouts）、4.11（デモのレーン）、9 章（E2E）、10 章 9（テストの設定、検証すること）を合わせた
