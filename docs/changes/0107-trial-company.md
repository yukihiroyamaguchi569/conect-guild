# #107 お試しの会社を作るスキル（2026-10-15）

- 入口の 3 段（0 デモ／1 お試しの会社／2 自分の会社）の 1 として、架空の会社「お試し商会」を作るスキル `/guild-trial`（`.claude/skills/guild-trial/SKILL.md`）を足した（10 章 9）。Issue #107 のうち「作る」だけで、「片付ける」は別の PR にする（司令塔の判断。スキルには「準備中」と 1 行だけ書いた）
- 聞くのは部門の数（2〜6、既定 4）と、GitHub にリポジトリを作る前の 1 回の承認だけ。置き場は `~/guild-trial/<日付>-<4 文字の乱数>`、リポジトリは同じ名前の private（司令塔の指示）
- 部門が 4 でないときは、雛形の 4 部門に 5 番目の開発（`dev/`、ラベル `dev`）、6 番目の営業（`sales/`）を足した表の上から使う（司令塔の指示）。営業のラベルは、指示に無かったので、1〜4 部門にそろえて `営業` にした（実装時の判断）
- 司令塔と部門の `CLAUDE.md` は手で書くと量が多く間違えやすいので、書くだけの道具 `npm run trial:scaffold` を足した。docs/orchestration.md の雛形（4 章・5 章）をその場で読んで埋め、写しを持たない（雛形と食い違わないため。実装時の判断）。部門の数が 2・3 で総務が無いときは、「どこにも当てはまらない依頼」を最後の部門に振る（4 章の書き換えの決まりに従った）。その部門の担当と担当範囲にも「ほかに引き取り手のない仕事」を足した（担当外として差し戻して往復しないため。統合レビューの指摘）。`<owner/name>` は道具の引数を置き場と部門の数だけにしたため、スキルが Edit で埋める
- `guild.settings.local.json` が既にあれば、何も作らずに止まる。`settings:write` にも `--overwrite` を付けない（本物の会社の設定を壊さないため。司令塔の指示）
- スキルは `gh api user` で取ったアカウント名を、GitHub のアカウント名の形（英数字とハイフンの 1〜39 文字）か確かめてから使う（統合レビューの指摘）
- docs/setup.md の入口に 3 段の説明、README に 1 行を足した
