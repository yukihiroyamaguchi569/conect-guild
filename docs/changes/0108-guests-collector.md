# #108 お客さん: 設定・collector・snapshot v4（2026-10-14）

- 会社の外のプロジェクトのセッションを「お客さん」としてギルドに来させ、進み具合を見られるようにする。この PR は設定・collector・snapshot までで、画面（席、状態、掲示板の欄、出来事）は次の PR（計画の F）
- 社長の判断（2026-10-14）: お客さんは設定に名指しで並べたフォルダだけ、最大 2 人。セッションの状態に加え、リポジトリの Issue・PR を題名つきで見せる
- 設定: `guests: [{ name, sessionDir, repo? }]`（任意）。名前は重ならず、フォルダは会社のフォルダとも互いにも違い、`repo` は会社の `repo` と違う。今の設定ファイル（`guests` が無い）はそのまま通る。`settings:write` は出発点の設定の `guests` を残す（`/guild-setup` でお客さんを足すのは後の PR）（4.1）
- セッション: collector の席を会社とお客さん（設定の並びの番号）に一般化した。お客さんのフォルダも完全一致だけを拾い、ほかの行（お客さんのフォルダの下の別のフォルダを含む）は今までどおり何も残さない（4.7、2 章 5）
- GitHub: お客さんごとに 5 分おき、会社の 60 秒ごとの取得とずらして（20 秒・40 秒から）裏で取る。開いている Issue・PR と、直近 7 日に completed で閉じた Issue・マージした PR（最大 20 件）。Issue の一覧に `pull_request.merged_at` が載ることを公開リポジトリで確かめたので、pulls の一覧は足さず、お客さん 1 人につき 5 分に 2 回で済ませた（4.1）
- 失敗の切り分け: お客さんごとに最後に成功した結果を持ち、お客さんの失敗は会社の部分・状態ファイル・snapshot の書き込み・`--once` の終了コードに影響しない。ログはお客さんを番号で書き、名前・リポジトリ名・題名は出さない（4.1）
- snapshot を v4 にした: `sessions.guests`（状態だけ）と `guests`（リポジトリ・取得時刻・開いているもの・最近の完了。お客さんの名前とフォルダは入れない）。画面は v4 を読み、設定と数か `repo` が 1 人でも合わなければ、お客さんの分を全員まとめて無視する（止めない。collector が前の設定のまま動いている印で、状態の並びも前の設定のものかもしれないため）。お客さんはまだ画面に出さない（4.2、5 章）
- 実装時の判断: 開いている Issue・PR の数に上限は置かなかった（大きなリポジトリでは 100 件ごとに 1 回の呼び出しが増える。画面の PR で表示の上限と合わせて見直す）
