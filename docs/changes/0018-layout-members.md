# #18 部門の数を変えられるようにする作り替え: 使うメンバーと間取り（2026-10-14）

- 部門の数を 2〜6 で変えられるようにする（#18）ための作り替え。見た目とふるまいは変えず、いまの 4 部門の画面のまま
- 設定（`packages/snapshot/src/settingsSchema.ts`）
  - `members` を任意の項目の表（`z.partialRecord`）にし、かなめ・王様・各部門のメンバーだけを必須にした。いまの `guild.settings.json` はそのまま通る
  - 部門の数の確かめを「ちょうど 4」から `SUPPORTED_DEPARTMENT_COUNTS`（いまは 4 だけ）に替えた。間取りを足すたびに広げる。エラーの文言は #18 を挙げたまま
  - 使うメンバーの並び `ACTIVE_MEMBER_IDS`（かなめ・部門の順のメンバー・王様）と `LEVEL_MEMBER_IDS`（かなめと部門のメンバー）、id ごとの表を作る `byMember` を足した
- 画面のメンバーの繰り返し（director・idle・idleCrew の並び、remarks・summons の順、partyLevel、乱数の種）を、これらの並びと `byMember` で作るようにした。キャラごとの絵・手の位置・セリフはすべての id を網羅したまま
- 間取り（新しい `apps/web/src/render/layouts/`）
  - `GuildLayout` に床・家具・小物・机（席、上段か下段、部門の小物、おしゃべりの相手）・かなめと王様の席・カウンター前と玉座の横・舞台裏（扉のそば）・お客さんの場所 2 つ・パーティ窓の下端・投げる距離を持たせた。いまの地図を `layout4.ts` にそのまま移した
  - `layoutFor(部門の数)` で選び、無い数は止める。`SELECTED_LAYOUT` は設定の部門の数から選ぶ。`LAYOUTS` と `layoutFor` は設定を読まない `catalog.ts` に置き、実際の設定を読まない `guildFromSettings.ts`（#18 の準備で分けたもの）から使う。`guildFromSettings(settings, layout)` の席は間取りの机から引き、`guild.config.ts` は実際の設定と `SELECTED_LAYOUT` を渡す
  - `map.ts`・`decor.ts`・`seating.ts`・`layers.ts`・`drawDaylight.ts`・`animatedDecor.ts`・`trinkets.ts`・`idleSpots.ts` に間取りを受け取って作る関数を足し、これまでの名前の export は選んだ間取りから作る（呼ぶ側は変えていない）。`guild.config.ts` の席と `scenes.ts` の `DEFAULT_SEATS`、`TOSS.maxTiles` も間取りから引く
  - 机ごとの表（部門の小物、旗の側、おしゃべりの相手）は机の番号で持ち、`departments[i].member` でメンバーに対応させる。部門の無いメンバー（いまはいない）の席は舞台裏で、描かない
  - 4 部門のお客さんの場所は、左下の地図の机の前とスツールの横の 2 マスにした（実装時の判断。歩けて、窓に隠れず、扉から行ける）。小物は動かしていない。お客さん自身は #108 で足す
- レベル（`domain/levelUp.ts`・`domain/baseline.ts`）
  - 保存するレベルを、かなめと設定の部門のメンバーだけの表にした。前回のレベルに無いメンバー（新しく加わった人）にはファンファーレを出さない
  - 差分の基準に部門 → メンバーの対応の指紋 `crew` を足した。対応が変わったら、レベルアップを出さずに今回のレベルを基準にし直す。`crew` は任意の項目なので、前に保存した基準もそのまま読める。その場合は対応が分からないので、更新後の最初の 1 回だけレベルアップを出さない（実装時の判断。クリアなどほかの出来事は出す）
- テスト
  - 作り替えの前の地図・家具・小物・席・遊び場・重なりを 1 行ずつ書き出したファイル（`render/layouts/__golden__/layout4.txt`）を先に記録し、作り替えの後も同じことを確かめる
  - すべての間取りに共通の検査（席にカウンター前から歩いて行ける、席と頭上の吹き出しが窓に隠れない、お客さんの場所が歩けて窓に隠れず扉から行ける、小物が席に乗らない、机の数＝部門の数、おしゃべりの相手が対になっている）を `layouts.test.ts` に足した
- DESIGN.md の 3 章（構成）、4.4、4.6、10 章 9（検証すること）を合わせた
