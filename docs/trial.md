# 架空の会社を作って試す

自分の会社の準備ができていなくても、架空の会社「お試し商会」を作って、GitHub の本物のリポジトリに置いた架空の Issue で画面を試せます。

**用意するもの**

- Node.js 26.10 以上
- Claude Code
- `gh` でログインしていること（`gh auth status` で確かめます）。private のリポジトリを作る権限が要ります
- conect-guild の clone と `npm ci --ignore-scripts`。README の「[デモを見る](../README.md#1-デモを見る)」で済ませていれば要りません。作る道具がワークスペースのパッケージを使うので、無いと動きません

  ```bash
  git clone https://github.com/yukihiroyamaguchi569/conect-guild.git
  cd conect-guild
  npm ci --ignore-scripts
  ```
- `guild.settings.local.json` が無いこと。あると、自分の会社の設定を上書きしないよう、何も作らずに止まります

**あなたがやること**

番号の手順があなたのやることです。「→ スキル:」の行は、その間に `/guild-trial` がやることです。

1. conect-guild の直下で Claude Code を起動し、`/guild-trial` を実行します（「お試しの会社を作って」でも使われます）
2. 部門の数を聞かれたら答えます（2〜6。決めていなければ 4）
3. 作るものの一覧が出たら、確かめて承認します。承認を求められるのは、リポジトリを作る前のこの 1 回だけです
   - → スキル: GitHub に private のリポジトリ `<あなたのアカウント>/guild-trial` を作り、部門のラベルと架空の Issue を置きます。片付けで見分けるため、説明に「conect-guild のお試し商会（架空の会社）」が入ります
   - → スキル: 手元に司令塔のフォルダ `~/guild-trial/guild-trial` と、その下の部門のフォルダを作ります（それぞれ `CLAUDE.md` 付き）
   - → スキル: 手元の設定 `guild.settings.local.json` を書きます
   - → スキル: 同じ名前のリポジトリかフォルダが既にあれば、`guild-trial-2`、`guild-trial-3` … と番号を足した名前にします
4. 許可を求められたら許可します。手元のフォルダを書くときと、`npm run dev:all` を起動するときの 2 回です（どちらも Claude Code の sandbox の外で動かすため）
   - → スキル: `npm run dev:all` を起動し、collector が集め終わるのを待って、開く URL を伝えます。既に `npm run dev:all` が動いていたら止めずに、止めて起動し直すよう伝えます
5. スキルが終わったら、司令塔と部門のセルを開きます
   - MulmoTerminal なら、Claude Code で `! npm run trial:open-cells` を打ちます。司令塔と部門のセルがまとめて開くので、各セルの「信頼しますか？」に答えます。Claude Code の安全確認で止まるので、スキルは代わりに実行しません。お試しの会社の設定のときだけ動き、MulmoTerminal が動いていなければ何も開きません
   - ほかの端末では、司令塔のフォルダと部門のフォルダをそれぞれ開いて Claude Code を起動します（フォルダそのもので起動します。[orchestration.md の 3-5](orchestration.md#3-5-部門のセッションを開く)）
6. ブラウザで http://127.0.0.1:5273 を開きます。「デモ表示中」の帯が消え、お試しの Issue が部門の机に配られていれば成功です。MulmoTerminal でセルを開いたなら、`npm run dev:all` の出力が `sessions=<部門の数 + 1> ok` になり、画面にもセッションの動きが出ます

**片付け**

お試しの会社を消したい場合は、`/guild-trial-cleanup` を実行します。消すものの一覧（リポジトリ、手元のフォルダ、手元の設定、集めたデータ）と、動いていれば止める画面（5273 番の開発サーバー）を見せ、承認を 1 回もらってから消します。消すリポジトリとフォルダは、スキルが `npm run trial:check` でお試しの会社のものと確かめたものだけです（`gh` を呼ぶので sandbox の外で実行し、許可を求められます）。画面はスキルが PID を名指しして止めます（collector も一緒に止まります）。リポジトリを消すには `gh` に `delete_repo` の権限が要ります。足りなければスキルが案内するので、自分で `gh auth refresh -h github.com -s delete_repo` を実行します。片付けたあとは手元の設定が無くなるので、画面の帯の扱いは [setup.md の 3 章](setup.md#画面の帯に失敗が出る手元の設定が無いとき)のとおりです。MulmoTerminal の最近のフォルダに残ったお試しのフォルダは、`! npm run trial:open-cells -- --forget` で外せます（もう無いお試しのフォルダだけを外します）。チップの × で 1 つずつ外してもかまいません。

**自分の会社にする（リニューアルオープン）**

お試しの会社が気に入ったら、そのまま自分の会社として使い続けられます。conect-guild の直下で `/guild-trial-renew` を実行します（「お試しの会社を自分の会社にしたい」でも使われます）。聞かれるのは、新しい会社の名前（GitHub のリポジトリ名と手元のフォルダ名。英小文字・数字・ハイフン）と、変える前の承認の 2 回だけです。似た名前のリポジトリがあれば、別の会社として作ってよいかも聞かれます。

先に、開いているお試しのセルを閉じ、`npm run dev:all` を止めておきます（フォルダが移るため。スキルは画面を止めません）。スキルは、変える前と、リポジトリの名前を変える・フォルダを移す直前に、`npm run trial:check` でお試しの会社のものかを確かめ（許可を求められます）、次の順に変えます。

1. リポジトリの説明を `<新しい名前> の会社` に変える（片付けがお試しと見分ける印を最初に外します）
2. 司令塔と部門の `CLAUDE.md` から、お試しの印の行（「これは conect-guild を試すための架空の会社「お試し商会」のものである。…」）を消し、司令塔の `CLAUDE.md` に書かれたリポジトリ名を新しい名前に直して、`main` に直接 commit・push する
3. リポジトリの名前を `<新しい名前>` に変え、手元の `origin` も合わせる
4. フォルダを `~/guild-trial/<お試しの名前>` から `~/<新しい名前>` に移す
5. 手元の設定 `guild.settings.local.json` の `repo`・`commanderSessionDir`・部門の `sessionDir` を書き直す（前の設定は `.bak` に残ります）
6. 架空の Issue（題名が「お試し: 」で始まり、本文が決まった文のもの）を not planned で閉じる

部門（名前・ラベル・フォルダ・部門の数）はリニューアルオープンでは変えません。変えたいときは、リニューアルオープンのあとで司令塔に頼みます（[orchestration.md の 1 章](orchestration.md#1-登場する役割)の最後の段落）。前の形の名前 `<日付>-<4 文字>` のお試しは、リポジトリに説明が無く片付けの対象から外せないのでリニューアルオープンできません（片付けて作り直します）。

リニューアルオープンのあとは `npm run dev:all` で起動し直し、MulmoTerminal などで `~/<新しい名前>` と部門のフォルダでセルを開き直します。`npm run trial:open-cells` はリニューアルオープンした会社では動きません。最近のフォルダに残った古いお試しのフォルダは `! npm run trial:open-cells -- --forget` で外せます。リニューアルオープンした会社は `/guild-trial-cleanup` の対象になりません（要らなくなったら自分で消します）。1 の説明を変えたあとなら、途中で止まっても、GitHub のリポジトリは片付けで消されない状態になっています。リニューアルオープンが終わるまで `/guild-trial-cleanup` は使わず、スキルに続きを頼みます。
